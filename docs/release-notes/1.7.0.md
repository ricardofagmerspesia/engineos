## EngineOS v1.7.0

_Released 2026-09-05_

### Summary

The node runtime. Every path EngineOS executes — the nine hooks, the kernel,
the exec journal and telemetry writers, the project scaffold, the bypass switch,
the two agent generators, the eval runner, the perf bench, the usage report, the
installer's settings merge and the 62-check validator — now runs from one
TypeScript bundle, `dist/engineos.cjs`, on `node >= 18`. `jq` and `python3` are
no longer needed by anything shipped, `hooks/hooks.json` registers node
directly, and every bash entry point that consumers call is a two-line shim over
the bundle. The fifteen bash test suites are ported to `node:test` and deleted;
`npm test` is the one test runner. Nothing is removed or renamed; every shim is
deprecated with a window that closes in 2.0. See `docs/COMPATIBILITY.md`
`## 1.7.0 additions`.

### Added

#### `dist/engineos.cjs` — one runtime entry point

`node dist/engineos.cjs <command>` with the arms `kernel`, `journal`,
`telemetry`, `hook`, `init`, `bypass`, `gen`, `evals`, `bench`, `usage-report`,
`validate` and `settings-merge`. The arm names and their stdout and exit
contracts are public surface from this release (`docs/COMPATIBILITY.md`
`## What is public surface`). A node-version guard runs before anything else:
below 18 the hooks that inject context exit 0 silently, the others emit a
`[engineos] <hook> skipped: node >= 18 required` system message, and the CLI
arms fail with the same sentence.

#### `engineos kernel resolve`

One `resolve --facts '<json>'` arm over the decision kernel. The fourteen
existing arms (`route-path`, `route-intent`, `model`, `risk`, `gates`, `repair`,
`admit`, `breaker`, `hitl`, `waves`, `decision-rules`, `scale`,
`route-escalate`, `resolve-task`) are projections of its sparse answer, and a
differential suite asserts their output stayed byte-identical. An unknown fact
key is refused, not ignored.

#### `engineos settings-merge`

The installer's `settings.json` work — scrub prior EngineOS hook entries in
either the `.sh` or the node form, append the current list, set-union
`permissions.allow` — as one subcommand. `install.sh` and `install.ps1` call it;
neither needs `jq`.

#### Hooks registered as node

`hooks/hooks.json` registers `node "${CLAUDE_PLUGIN_ROOT}/dist/engineos.cjs"
hook <name>`. On Windows this is the fix for the Git Bash terminal window that
used to open on every hook fire: nothing on the hook path resolves a `.sh`
through a file association any more. `bash.exe` is no longer looked up or
registered by `install.ps1`.

#### `engineos validate` — the integrity checks in-process

All 62 checks are registered in `src/checks/index.ts`, one module per family,
each reporting findings (`[<code>]` / `[<code>:<subject>]`) that the harness
renders. Same ids, same `ok`/`FAIL`/`skip` verdicts, same header, summary and
exit codes as `scripts/validate-engineos.sh`, which is now a shim. C1 asks for
`node >= 18` where it used to ask for `jq`.

#### e2e suites under `npm test`

Nineteen `*.e2e.test.ts` files spawn the committed bundle black-box, one test
per former bash assertion. CI's dist drift guard runs before them so a stale
bundle fails as drift, not as a test assertion. Test count at release: 1961.

### Changed

#### Every bash entry point is a shim, deprecated

`scripts/kernel.sh`, `scripts/exec-journal.sh`, `scripts/telemetry.sh`,
`scripts/init-project.sh`, `hooks/bypass.sh`, the nine `hooks/<name>.sh`,
`scripts/gen-agent-commands.sh`, `scripts/gen-agent-registry.sh`,
`scripts/run-evals.sh`, `scripts/bench-runtime.sh`, `scripts/usage-report.sh`
and `scripts/validate-engineos.sh` each `exec` the bundle with `ENGINEOS_ROOT`
set to their own root. Stdout, stderr and exit codes are unchanged. All are
deprecated in 1.7.0 and removed in 2.0; call the `engineos <arm>` form to get
ahead of that. `scripts/kernel.sh` still needs a bash on Windows until then.
`hooks/layout-manifest.sh` and `hooks/scaffold-layout.sh` are not shims and not
deprecated: they are frozen bash that `engineos init` sources until 2.0.

#### Dependencies: `jq` and `python3` out, `node >= 18` in

The installers, the hooks, the generators, the eval runner, the usage report and
the validator no longer call `jq`; the bench no longer calls `python3`. `node >=
18` is required to install, not only to run hooks: without it the installers
register nothing and print the by-hand fallback. Working on the repo needs node
and `shellcheck` (for `install.sh` and the shims). CI's "Tools present" step
checks exactly those; JSON validation, the validator, the evals and the bench
run through `node dist/engineos.cjs` directly.

#### Bash libraries deleted

`hooks/lib-common.sh`, `hooks/lib-runner.sh` and `hooks/docs-ledger.sh` are
gone with the suites that sourced them. `install.sh`'s `ENGINEOS_HOOK_LIBRARIES`
is `"layout-manifest.sh scaffold-layout.sh"`; check C30 reads that list.

#### Version

`.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` and
`package.json` 1.6.0 -> 1.7.0. `registries/policy.json` `version` stays 1.6.0:
no policy block changed shape in this release.

### What Was Fixed

#### `kernel.sh risk` and the partial-registry class fail closed

The kernel refuses a partial or unparseable registry with its `{"error": ...}`
shape instead of answering from `null` (`fix(kernel): fail closed on partial
registries`). `admit`'s argument loop no longer accepts a dangling flag.

#### Scaffold writes stay inside the project root

`engineos init` and the SessionStart scaffold contain every write to the target
project: a dangling seed symlink or a symlinked directory in a hostile repo can
no longer redirect a write outside it (`fix(scaffold): contain layout writes to
the project root`).

#### Journal timestamps and schema fields are pinned

`engineos journal append` guards the timestamp it generates and pins the schema
field set, so a v2 span cannot carry an undeclared field (`fix(journal)`).

#### Check ids and agent tiers

The agent-tier check is C31, resolving a collision with an existing id; agent
tiers are read from `registries/models.json`, so a tier the registry does not
declare fails validation instead of passing silently.

### Upgrade

Machine install, once, after `git pull`:

```bash
cd ~/projects/engineos && ./install.sh
```

Windows: `install.ps1`. Either installer rewrites the hook entries in
`~/.claude/settings.json` from the `.sh` form to the node form and removes the
old ones, so no hook ends up registered twice. Have `node >= 18` on the PATH
Claude Code uses; nothing else is needed. Child projects need no change.

If you call a shim from your own tooling, it keeps working through 1.x. To be
ready for 2.0, replace `scripts/kernel.sh <arm>` with `node <engineos>/dist/engineos.cjs kernel <arm>`
and likewise for the other shims; the answers are identical.

### What 1.7.0 does NOT do

- **Nothing is removed.** Every shim, rule path, agent name, alias, command,
  skill directory and hook event contract of 1.6.0 is still there. Removal is
  2.0.
- **`scripts/kernel.sh` still needs a bash on Windows.** Only the hook path
  dropped Git Bash. Windows callers of the kernel shim keep Git Bash until they
  move to the node form.
- **`engineos init` still shells out to bash.** `hooks/scaffold-layout.sh` and
  `hooks/layout-manifest.sh` stay as frozen bash because a sourced function
  cannot be shimmed; the scaffold becomes TypeScript in 2.0.
- **No published npm package.** `dist/engineos.cjs` is committed and consumed
  from the checkout; `npm i engineos` is not a thing.
