### Summary

Intent routing stops being an any-match over literal phrases and becomes a
three-tier router. Tier 0 is the deterministic gates, which always win. Tier 1
is a scored TypeScript classifier. Tier 2 is escalation to the `router` agent.
On top of that sits an opt-in semantic judge (TypeSafe Jev) that can only add
gates or raise risk, and that ships in `shadow` mode behind an environment
switch. Two further opt-in tiers arrive: an embedding tie-break daemon and an
in-process Claude Code adapter. The five per-call hooks move to a smaller hot
bundle. Nothing in the public surface is removed. Every change is MINOR
(`docs/COMPATIBILITY.md` `## Unreleased`; ADR
`docs/adr/2026-10-10-three-tier-router-and-jev-judge.md`; contracts
`docs/specs/2026-10-10-routing-replacement-contracts.md` rev 4).

### Breaking Changes

None. Additive answer keys are appended at the end and existing key order is
kept. `validate` gains new failing checks and findings, which is MINOR under
`docs/COMPATIBILITY.md` (see "Compatibility notes").

### What's New

#### Three-tier scored router

- `registries/intents.json` 2.0.0 gives every row optional `phrases` (weighted),
  `verb_object` pairs, `negative` weights, 3 to 10 `exemplars` (scored with
  BM25), a per-intent `threshold` and `router_row` cells. `signals` is still
  read, and stays through 1.x.
- `kernel route-intent` and `resolve --facts {prompt}` append `ranked`
  (id, score, confidence, features) and `margin`. `matches` keeps its
  eleven-field shape and registry order, capped at `router.scoring.max_intents`.
  The cap trims only exemplar-assisted admissions. High-floor intents, and
  intents whose declared phrases alone clear `min_score`, are always kept
  (contracts rev 4 §1.5). Calibrated v2 phrases can add intents that the v1
  any-match never routed: a nine-domain prompt that names "record an ADR" now
  also routes `adr`.
- `route-escalate` and the `resolve-task` route section append `ranked`,
  `margin` and `judge`. A new escalation reason, `low-confidence`, is appended
  last.
- Text that starts with a `router.source_markers` prefix is not routed at all:
  no kernel call and no judge call, just one `route` event with
  `{ "skipped": "not-user-input" }`. Such text includes a task notification,
  a tool result or an `[engineos]` echo. This closes the case where a
  subagent's background notification was routed as a seven-intent high-risk
  dispatch.
- `engineos gen router-table` generates the router table in `CLAUDE.md` and
  `AGENTS.md`, between `<!-- engineos:router-table:begin -->` and
  `<!-- engineos:router-table:end -->`, from `registries/intents.json`.
- The `[router]` line may end with `corrected_from=<id>[,<id>...]`, and
  `engineos usage-report` mines those corrections as misroutes.

#### Opt-in Jev judge (shadow by default)

- Off unless both `ENGINEOS_JUDGE=jev` and `TYPESAFE_API_KEY` are set. The key
  is read from the environment only and is never written to a file, log or span.
- Ships with `judge.mode: "shadow"`. Shadow reports `task_contract.judge` and
  `risk_proposal` but changes nothing. `advisory` also shows a judge note. Only
  `authoritative` folds judge facts into the task contract. Even then the fold
  is add-only for gates, raise-only for risk, and keeps every high-floor
  survivor. `route.*` is always the deterministic answer.
- The endpoint is pinned. The policy loader refuses any `judge.endpoint` whose
  origin is not exactly `https://api.typesafe.ai`, and that refusal fails the
  whole `policy.json` load. `key_env`, `enabled_env`, `enabled_value` and the
  redaction list's SHA-256 are also pinned in code. `max_state_bytes` is capped
  at 16384. `retries` accepts only `0`. `timeout_ms` is 400.
- Redaction comes before egress. The prompt is pre-capped, then 27 kinds of
  redaction patterns run (keys, tokens, private-key blocks and similar), each
  keeping only the prefix that provably agrees with redaction of the whole
  prompt, then the text is cut to the request limit. A secret straddling the
  cap is never sent in part; a capped prompt can lose some text near the cut.
  Patterns with unbounded quantifiers are refused at load time.
- The judge receives only user-typed prompts (`judgeMayReceive`, fail-closed):
  anything that looks like a tag frame is never sent.
- The judge's own breaker state lives under the consumer's git directory. Each
  call writes a `judge` telemetry event that carries no prompt text.

#### Opt-in embedding tie-break and in-process adapter

- **Embedding tie-break** (`ENGINEOS_EMBED_DAEMON=1`): a warm local MiniLM
  daemon (`tools/embedding-daemon/`, model pinned by revision) scores the
  candidates of an ambiguous deterministic route. The scores reach the kernel
  as a journaled `tiebreak` fact. They can only narrow existing survivors to one
  winner. They never add an intent, lower risk or edit `route.*`. The client
  (`src/judge/tiebreak.ts`) is in the shell bundle, the daemon is outside it.
  The tie-break stays inert while `router.scoring.threshold` and `margin` are
  `0`.
- **In-process adapter** (`ENGINEOS_INPROCESS=1`, plugin `engineos-inprocess`
  in `adapters/claude-code-mod/`): one warm Node host per session serves hook
  decisions. A presence record (v2) lets the shell hooks stand down for the
  hooks the host serves. `git-write-guard` never stands down. The mod abandons
  a host that misses a hook deadline. The registered `hooks.json` command hooks
  still spawn once per call and exit immediately, so this saves hook work, not
  spawns.
- Both tiers are documented in `docs/OPT-IN-TIERS.md`. Neither adds a
  dependency to the root `package.json`.

#### Hot bundle for per-call hooks

`route-before-change`, `announce-agent-dispatch`, `git-write-guard`,
`mark-unrecorded` and `announce-agent-return` now run
`node "${CLAUDE_PLUGIN_ROOT}/dist/engineos-hot.cjs" hook <name>`. Each committed
`dist/*.cjs` is now a small loader in front of its bundle under `dist/runtime/`.
On node 22.8+ the loader enables V8's compile cache, in a private per-user
directory only. `git-write-guard` gains a fast path that skips the tokenizer
when a command contains neither `git` nor `gh`. `engineos bench` adds a
`per-call hook bundle` budget (320000 bytes) and the scenarios `bash-noop`,
`hot-bundle-load` and `full-bundle-load`.

#### Validator

`engineos validate` has 72 registered check ids, and a full run on a clean tree
reports 117 results (`src/validate/validate.e2e.test.ts` `RESULT_COUNT`). The new
router family covers intents v2 well-formedness (C38), 3 to 10 exemplars per
active intent (C38b), the router and judge policy blocks plus isolation
boundaries such as "no `fetch(` under `src/judge/**`" (C38c), and router-table
drift (C38d). C18f gains `hook-target-missing`.

#### Golden set and baseline

`evals/intent-routing-cases.jsonl` grows to 284 cases. It holds 148 held-out
cases (145 graded) and 136 exemplar cases, and uses schema v2
(`expect_primary`, `expect_not_intents`, `exemplar`, `source`, `judge`).
Fallback-tier numbers on the held-out set (`evals/BASELINE.md`, before = the
`b0291ed` registries, after = this revision):

| Metric | Before | After |
|---|---|---|
| Macro precision | 0.854 | 0.935 |
| Macro recall | 0.609 | 0.965 |
| MRR@3 (n=102) | 0.858 | 0.990 |
| Exact cases | 69/145 | 125/145 |

On the untuned `para-*-3` subset (31 cases, the only out-of-sample fallback
number), macro precision went 0.769 -> 0.926 and recall 0.306 -> 0.871. The
three misroutes that motivated the change now pass on the fallback tier,
except the notification case's hook path, which is still pending a run.

### What Was Fixed

#### Misroutes from literal phrase matching

"agent" no longer sends Claude Code tooling requests to the `llm` row, and an
architecture plan routes `adr` instead of `new-feature`. A bare "pipeline"
no longer routes `devops`: only delivery-scoped wording does.

#### Tie-break gap tolerance

A tie-break gap exactly equal to `router.tiebreak.margin` is now accepted, as
contract §4.7 states. Float subtraction error is absorbed by a 1e-9 tolerance.

#### Security fix pass

Presence record v2, the pinned judge endpoint and fields, bounded redaction,
the add-only authoritative fold, and abandoning an unresponsive in-process host
(contracts rev 4 §17).

### Compatibility notes

- All MINOR. `registries/policy.json` 1.7.0 -> 1.8.0 and
  `registries/decision-rules.json` 1.1.0 -> 1.2.0 (new `judge_fact` and
  `judge_threshold` per rule). The `intents.json` `signals` field enters its
  deprecation window, read through 1.x and removed in 2.0.
- Deprecated shell shims move to the Warn step and print one stderr line before
  `exec`. `ENGINEOS_QUIET_SHIMS=1` silences it.
- A consumer that copied only `dist/engineos.cjs` must also ship `dist/runtime/`.
- `engineos settings-merge` recognises the `dist/engineos-hot.cjs` command form
  and removes earlier EngineOS entries first, so no hook is registered twice.
- Bash parity: the `route-intent`, `route-escalate` and `resolve-task` arms of
  `src/kernel/parity.test.ts` are **kept**. They compare the legacy keys after
  stripping the trailing additive keys, over the pinned v1 fixture registries.
  Like every arm, they skip where `bash -n` cannot parse the pinned kernel,
  which includes macOS `/bin/bash` 3.2. CI's `verify` job sets
  `ENGINEOS_REQUIRE_PARITY=1`, which turns a skip into a failure, and is the
  control that enforces parity. Scored answers on the shipped registries are
  pinned by the golden set.
- New environment variables, all unset by default: `ENGINEOS_JUDGE`,
  `TYPESAFE_API_KEY`, `ENGINEOS_QUIET_SHIMS`, `ENGINEOS_INPROCESS`,
  `ENGINEOS_EMBED_DAEMON`, `ENGINEOS_EMBED_CACHE`, `ENGINEOS_EMBED_OFFLINE`,
  `ENGINEOS_EMBED_IDLE_MINUTES`. (`ENGINEOS_ROOT` and `ENGINEOS_NODE` are
  also read by the in-process tier; `ENGINEOS_REQUIRE_PARITY` predates this PR.)

### Rollback

Revert the merge commit of PR #132. The judge, the embedding tie-break and the
in-process adapter are all off by default behind their environment switches,
so a consumer who never set them sees only the router, hot bundle and validator
changes. A consumer who did set them can unset `ENGINEOS_JUDGE`,
`ENGINEOS_EMBED_DAEMON` and `ENGINEOS_INPROCESS` to return to the deterministic
path without reverting.

A machine whose `~/.claude/settings.json` was merged by the 1.8.0 installer
needs one manual step after a revert. The 1.7.0 `settings-merge` recognises an
EngineOS entry only by `dist/engineos.cjs` or `<root>/hooks/` in its command,
and `dist/engineos-hot.cjs` matches neither. Re-running the reverted installer
therefore adds the `dist/engineos.cjs` entries but leaves the five
`node ".../dist/engineos-hot.cjs" hook <name>` entries in place, pointing at a
file the revert removed. Delete those five entries by hand, then re-run the
installer.

### Known limitations

- **Judge not yet measured.** No judge request has left the machine. One live
  shadow call with the committed request was approved on 2026-10-11 and is
  blocked until `TYPESAFE_API_KEY` is set; the calibration of
  `judge.thresholds` is pending. Every judge-column number in
  `evals/BASELINE.md` reads "pending approved run".
- **Bench cells pending.** Every hook-latency scenario, the runtime budget
  actuals, the `scoreIntents` cost and the judge latency p50/p95 are pending an
  approved `engineos bench` run.
- **Tie-break thresholds are placeholders.** `router.tiebreak.min_similarity`
  (0.6) and `margin` (0.1) need the pinned MiniLM daemon to calibrate.
- **Authoritative-mode latency budget.** In `authoritative` mode with both the
  judge and the tie-break enabled, the judge (up to about 450 ms: 400 ms
  timeout plus 50 ms guard slack) and then the tie-break (up to 150 ms) run in
  sequence before the kernel call (`src/hooks/prompt-judge.ts`
  `consultSemantics`). A prompt can therefore exceed the 600 ms prompt-advisor
  budget. `shadow`, the shipped mode, runs the two in parallel.
- **In-process adapter saves work, not spawns.** See `docs/OPT-IN-TIERS.md`
  "Known gaps (host API)".

### Upgrade

Machine install, once, after `git pull`:

```bash
cd ~/projects/engineos && ./install.sh
```

Windows: `install.ps1`. The installer rewrites the five per-call hook entries
to the `dist/engineos-hot.cjs` form. Child projects need no change. To try the
judge on one machine, set `ENGINEOS_JUDGE=jev` and `TYPESAFE_API_KEY` in your
own environment; it stays in `shadow` mode. Do not enable it as a team default
before the security review of `src/judge/**` and zero-data-retention terms
(ADR consequences).
