## EngineOS v1.6.0

_Released 2026-09-03_

### Summary

Runtime governance. Before this release EngineOS could answer what it had
DECIDED — route, risk, autonomy, gates — and nothing about what happened while
agents ran, what to do when work arrived faster than the wave cap drained it, or
when a human must decide and why. 1.6.0 adds three kernel answers
(`admit`, `breaker`, `hitl`), an agent-span journal with its first real writers,
retrieval metrics for RAG features, and a one-command adoption path for child
projects. Nothing is removed or renamed; see `docs/COMPATIBILITY.md`
`## 1.6.0 additions`.

### Added

#### Backpressure: `kernel.sh admit`

`scripts/kernel.sh admit --inflight <n> --queued <n>` answers
`{action, capacity, reason}` where `action` is `dispatch`, `defer` or `reject`.
Capacity IS `parallelism.wave_concurrency_cap` — never a second copy of the
number — and the queue bound is `parallelism.backpressure.max_queued_units`
(12). At cap with a full queue the reason names the HITL trigger
`budget-exhausted`. Mirrored in `rules/parallelism.md` `## Backpressure`;
checked by C24.
ADR: [`docs/adr/2026-09-03-backpressure-reuses-wave-cap.md`](../adr/2026-09-03-backpressure-reuses-wave-cap.md).

#### Circuit breaker: `kernel.sh breaker`

`scripts/kernel.sh breaker` is a per-resource transition table answering
`{state, allow, reason}` over `closed`, `half-open` and `open`. It is the third
failure block and deliberately not a variant of the other two: `retry` counts
attempts on a UNIT, `repair` counts attempts on a CHECK, `breaker` counts
consecutive failures on a RESOURCE (`provider`, `mcp`, `tool`, `agent`).
Consult it before `retry`. Mirrored in `rules/parallelism.md`
`## Circuit breaker`; checked by C25.
ADR: [`docs/adr/2026-09-03-circuit-breaker-separate-from-retry.md`](../adr/2026-09-03-circuit-breaker-separate-from-retry.md).

#### Human-in-the-loop as a kernel entity: `kernel.sh hitl`

`scripts/kernel.sh hitl --risk <tier> --autonomy <A0..A4>` answers
`{required, reasons, autonomy_after, record_home}`. `policy.hitl.reasons` is a
closed eight-id vocabulary, so a gate can no longer cite a reason nobody
enumerated. `autonomy_after` is a one-level DROP that never raises and never
goes below A1. `resolve-task` folds the answer in as `.hitl`, and only from a
CLASSIFIED tier — never from a risk floor. `hooks/prompt-advisor.sh` announces
it and emits a new `hitl` telemetry event. Mirrored in `rules/risk-autonomy.md`
`## Human-in-the-loop`; checked by C26.
ADR: [`docs/adr/2026-09-03-hitl-as-kernel-entity.md`](../adr/2026-09-03-hitl-as-kernel-entity.md).

#### Agent spans: exec-journal v2

`scripts/exec-journal.sh append` gained twelve optional span fields —
`--trace-id --span-id --parent-span-id --span-kind --tool --provider --model
--cost-micros --retry-attempt --cache-hit --route --risk` — and `validate`
gained the matching predicate. A v1 line carries none of these keys and stays
byte-identical and valid; backward compatibility is the contract. One session is
one trace (`trace_id` = session id). Four hooks are its first real writers:
`announce-agent-dispatch.sh` plus `announce-agent-return.sh` write `agent`
spans as a pair, `prompt-advisor.sh` writes `router`, `stop-verify.sh` writes
`verification`. Registered as `registries/policy.json`
`telemetry.exec_journal`, mirrored in `rules/observability.md`
`## Agent traces`; checked by C27.
ADR: [`docs/adr/2026-09-03-spans-extend-exec-journal.md`](../adr/2026-09-03-spans-extend-exec-journal.md).

#### One-command adoption: `/engineos:init`

`scripts/init-project.sh` plus the `/engineos:init` slash command replace the
manual adoption ritual, both backed by a single shared scaffold function
`hooks/scaffold-layout.sh` that `hooks/ensure-project-layout.sh` now sources
instead of carrying its own copy. `ENGINEOS_SCAFFOLD` was left in place —
retiring it would be a public-surface deprecation this release does not decide.
Checked by C29.
ADR: [`docs/adr/2026-09-03-init-project-over-env-flag.md`](../adr/2026-09-03-init-project-over-env-flag.md).

#### RAG retrieval metrics

`rules/llm-apps.md` `## RAG` now names the retrieval metrics (Recall@K,
Precision@K, MRR) and the generation criteria (groundedness, faithfulness),
requires a retrieval baseline at `evals/<feature>/retrieval/BASELINE.md`,
mandates hybrid dense+lexical retrieval with a re-ranker (opt-out only against a
recorded Precision@K measurement), and requires a per-corpus freshness policy.
Formulas and scorer implementations are in
`skills/eval-harness/references/retrieval-metrics.md`. Checked by C28.

#### `docs/adr/` and `docs/release-notes/`

Both directories are named by existing policy — `rules/memory.md` points ADRs at
`docs/adr/`, `docs/COMPATIBILITY.md` points removal-version records at
`docs/release-notes/` — and neither existed. `docs/adr/` now holds a README and
the five ADRs above; `docs/release-notes/` holds this file.

#### Agent-memory architecture: design only

`docs/specs/2026-09-03-agent-memory-architecture-design.md` names four memory
tiers over the knowledge homes EngineOS already has and specifies the missing
promotion detector `kernel.sh promote-candidates`. **Nothing in it is
implemented.** There is no `policy.memory` block and no `promote-candidates`
subcommand in 1.6.0.

### Changed

#### `telemetry.events[].written_by` is an array

Was a string, is now an array of strings, on all four events. One event can have
several writers, and the reverse C22c assertion now catches an undeclared
second writer. This supersedes the one-writer-per-event shape recorded in
`docs/specs/2026-08-06-decision-kernel-p7-telemetry.md`; that spec was
deliberately not rewritten (it records what was true then) and
`telemetry.note` carries the supersession instead. Migration is in
`docs/COMPATIBILITY.md` `### The one shape change consumers can break on`.

#### `exec-journal.sh validate` rejects non-slug identifiers

In 1.5.0, `run_id`, `capability_id` and `agent` accepted any string. They must
now match `^[A-Za-z0-9@_./:-]+$`, the same class the v2 span fields use, and
`validate` rejects a line where one of them does not. No producer of this
journal exists outside this repo's own hooks, so nothing is known to break in
practice — it is still a behaviour change in a shipped validator, which is why
it is here rather than in a PATCH.

`note` remains free text on purpose and is the ONE field that admits it. The
containment claim in `rules/observability.md` and `registries/policy.json` is
scoped exactly that way: every field except `note` is a slug. An earlier draft
of that claim said no field admitted text at all, which was false while those
three accepted one; it was corrected before release.

#### Version

`.claude-plugin/plugin.json` 1.5.0 -> 1.6.0, matching
`registries/policy.json` `version`, which the kernel work had already moved to
1.6.0.

### What Was Fixed

#### `kernel.sh risk` no longer fails open on an empty payload

`kernel.sh risk --signals '{}'` used to answer `low` with an `A2` autonomy
ceiling, so a caller that forgot to pass evidence was handed the loosest gate in
the system. It now returns the kernel's `{"error": ...}` shape and exits
non-zero: an empty payload is not low risk, it is no evidence. Any caller
relying on the old default gets an error where it previously got a tier.

The same fail-open class was closed by construction in the two new blocks:
`breaker` and `hitl` both error when their registry block is absent rather than
answering from `null`.

#### `docs/adr/` and `docs/release-notes/` resolve

`rules/memory.md` and `docs/COMPATIBILITY.md` both referenced directories that
did not exist, so two policies pointed at nothing. Both now resolve.

### Upgrade

Child projects, once:

```bash
cd <project>
~/projects/engineos/scripts/init-project.sh
```

Or, inside a Claude Code session in the project: `/engineos:init`. Add
`--dry-run` to see what it would do first. It is idempotent and never
overwrites a file you already have; it creates the `.engineos/` + `docs/`
layout (the opt-in signal every hook reads) and drops a deltas-only
`CLAUDE.md` only if the project has none. Exit codes: `0` ok, `1` no usable
machine install, `2` not a git work tree, `3` refused because the target is the
EngineOS repo itself, `64` bad usage.

Nothing else is required to consume 1.6.0. Everything above is additive; no
rule path, agent name, alias, command name, skill directory or hook event
contract changed.

Two exceptions, if either describes you:

- **You read `registries/policy.json` from outside this repo.** Handle
  `telemetry.events[].written_by` as an array — see the migration snippet in
  `docs/COMPATIBILITY.md`.
- **You write to the exec journal.** `run_id`, `capability_id` and `agent` must
  now be slugs, or `exec-journal.sh validate` rejects the line.

### What 1.6.0 does NOT do

Named here rather than left to be discovered.

- **Nothing obliges the orchestrator to ask.** `admit` and `breaker` are kernel
  answers; no scheduler or hook calls `admit` before a dispatch, and no
  running-agent count exists for one to read. The prose in
  `rules/parallelism.md` is what requires the ask.
- **Nothing writes breaker failure counts.** The consecutive-failure count is
  defined over `span_kind` `tool`/`model` FAILED spans, and no writer produces
  those spans yet. `breaker` ships as a resolver with fixtures and no production
  caller.
- **Seven of the eight `hitl` reasons have no in-repo producer.**
  `resolve-task` can emit exactly one, `high-risk`, via
  `decision_rules.any_high`. The other seven are reachable only by a caller
  invoking `kernel.sh hitl` directly with the matching flag or situation.
- **Agent spans carry no token or cost figures.** The dispatch hooks see no
  model usage, so `tokens_in`/`tokens_out` are 0 and `cost_micros` is absent. A
  0 there means unknown, never free. Real `tool` and `model` spans come from a
  headless runner that does not exist yet.
- **An agent span's `status` is a FLOOR, not a verdict.** It is read from three
  structural sources only — the harness's error flag, a top-level `.status` on
  an object response, and the envelope vocabulary as the first token of a string
  response. A failure reported inside prose reads `OK`. Nothing scans free text,
  on purpose. The count undercounts and is never a ceiling.
- **Span containment is structural, not semantic.** The CLI rejects a non-slug
  value; the hooks sanitize first (`hook_slug` maps every other character to
  `-`) so a span is recorded rather than lost. A harness-supplied
  `subagent_type` containing text therefore lands as a slug OF that text — for
  example `backend-coordinator\nSECRET=hunter2` becomes
  `backend-coordinator-SECRET-hunter2`. What the guard buys is that no field but
  `note` can carry whitespace, a newline, a quote or a control character, so
  nothing written through one can break the line format, smuggle a second JSON
  object or span two lines, and every value is capped at 256 characters with
  over-long rejected rather than truncated. The journal lives in `.git`, is
  opt-in behind `.engineos/` existing and `ENGINEOS_TELEMETRY` not being `0`,
  never runs in a bypassed session, and is reaped after 90 days.
- **`capability_id` on agent spans does not distinguish dispatches.** There is
  no `dispatch` capability and there should not be — C13 would require it to
  carry an agent binding and a model tier, and dispatching is what the
  orchestrator does, so there is no agent to bind. A consumer grouping agent
  spans by `capability_id` sees them all as `implement` and must disambiguate on
  `agent`.
- **Memory tiers are design only** — see Added, above.
