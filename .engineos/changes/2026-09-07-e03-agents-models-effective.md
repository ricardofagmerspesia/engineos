## What

Agents and models now exist as entities in the console, **read-only**, with real relations. And `GET /api/effective` shows the effective configuration by calling the kernel — the same binary the hooks call.

## Why

The console had one vertical out of five. Verticalizing the other four was item 1 of E03.

The scope decision that matters here is what was **not** done: agents and models went in **without an enablement switch**. Adding `enabled` to an agent today would recreate exactly the defect fixed hours earlier — a field the runtime does not read, presented in the interface as a control. A switch goes in after the runtime honors it, never before. Models have a reason of their own too: the tier table is checked against `rules/models.md` by an integrity check, so editing it here without moving the prose would leave the check red instead of changing behavior.

`/api/effective` closes the other half: showing what the system **is going to do**, not what the configuration seems to say.

## What was made

**Shared reader.** The frontmatter parser was private to `skills.ts`. Agents use the same dialect, and a second copy written by hand would drift: the two readers would end up disagreeing about quotes or about where the block ends, and the console would show one thing while the runtime read another.

**Agents.** The source is the frontmatter of `agents/*.md`, not `registries/agents.json` — the header of that file says it is generated by `scripts/gen-agent-registry.sh` and must not be edited by hand. Reading the generated copy would show the console a picture that may be stale relative to the files the operator is looking at.

The alias cost a correction worth recording. The obvious reading — an `alias:` key in the frontmatter — **would return null for all 22 agents**, because that key does not exist in any file of this repository: the generator extracts the alias from the literal text `Alias: <slug>` inside the block, and today it lives at the end of each `description:`. I had written the obvious version; running it against the real tree showed 22 nulls, which is the same always-empty-field defect this vertical exists to stop repeating. Fixed by mirroring the generator's rule: **19 aliases, exactly the 19 the generated registry carries.**

**Models.** One tier per entity, with the model, the escalation target, the routed work types and the agents that declare it. Resolved against the real tree: `build` with 16 agents, `design` with 5, `most-capable` with 1, `cheap` with none.

**Effective configuration.** `console/src/lib/kernel.ts` calls `scripts/kernel.sh` with `execFile` and argv as an array — the arguments are a path and a prompt provided by the operator. `GET /api/effective` returns `route-path`, `resolve-task` and `skill-state` together with the origin of each part. Suppressed skills appear as suppressed, with the reason.

## Verification

- `console: npm test` — **20 passed, 0 failed** (12 before; 8 new cases between agents and models).
- `console: npx tsc --noEmit` and `npx eslint .` clean.
- Run against the real tree: 22 agents, 0 with a parse error, 19 with an alias — matching `jq '[.agents[]|select(.alias!=null)]|length' registries/agents.json` = 19. Four tiers with real counts.
- Kernel seam exercised: `route-path` of a controller returns domain `backend`, five rules, `nestjs-patterns` and the agent; `resolve-task` returns the `skills`/`skills_suppressed` pair; `skill-state` returns `["strategy"]`; an empty path becomes a handled `KernelError`, not a raw exception.

Declared limitations:

- **There is no screen for any of this** — only the APIs. An operator still does not see agents, models or the effective configuration in the console.
- `npm run build` still has no local run (`next build` downloads the SWC binary and this session's network refuses). It runs in the CI `console` job, which has not had a real run yet.
- Agents and models are read-only. Nothing forces a new entity to enter `detectBaseConflicts` when they become editable.
- Nothing automatically verifies that `parseAgents` and `gen-agent-registry.sh` keep agreeing; the check of the 19 aliases was manual, in this session. A drift check between the two would require node and the console dependencies inside the check harness.
- MCPs, routing and rules remain without an entity. E03 stays **partial**.
