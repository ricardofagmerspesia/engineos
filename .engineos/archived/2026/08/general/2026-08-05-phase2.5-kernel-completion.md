## What
Kernel side of Phase 2.5 (units U1 and U2): a new `docs-writer` agent, and
capability bindings for `document` and the new `security-review`.

## Why
The ai-se-os runner is meant to hold no agent definitions of its own — the
kernel is the single agent inventory. Two gaps blocked that:

- **The kernel had no docs agent at all.** The runner's `document` state ran on
  a hardcoded placeholder prompt imitating a kernel agent that did not exist.
- **`security-review` had no capability entry**, so the runner's
  security-review state fell through to a fake executor that reviewed nothing
  and returned OK — a security gate that existed on paper only.

## Scope
`agents/docs-writer.md` (new), `registries/capabilities.json`,
`registries/agents.json` + `commands/agents/docs-writer.md` +
`commands/agents/tomasz.md` (all generated), `.claude-plugin/plugin.json`,
`.claude-plugin/marketplace.json`.

## Notes
Building this exposed a conflict with an earlier runner fix worth recording,
since it is the kind of thing that reappears: to see a `CRITICAL` verdict the
runner must parse the kernel's return envelope, but a prior fix had stripped
the whole `## Return format` section from dispatched prompts to remove an
engineos-only path reference — which would have left no agent ever emitting the
envelope the check depends on. Resolution: the section stays in the prompt and
only the kernel-internal references inside it are rewritten. A kernel agent's
envelope is now load-bearing for a consumer, not merely documentation.

Also observed, unrelated and not fixed here: engineos's global hooks fire
inside headless SDK sessions running in unrelated repositories — a T9 run
scaffolded `.engineos/` into a scratch repo uninvited. Belongs to hook gating,
tracked separately.
