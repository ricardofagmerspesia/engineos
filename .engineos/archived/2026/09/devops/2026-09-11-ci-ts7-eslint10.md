## What
Make CI green again on main after two dependabot bumps: TypeScript 7 (#94) removed
`moduleResolution: Node10`, and ESLint 10 (#99) removed the eslintrc compatibility
layer the console's `FlatCompat` config depended on.

## Why
Main has failed the `verify` and `console` jobs on every run since 2026-09-09.
Every PR opened since (including #102) inherits the red. Local gates did not catch
it because this machine's `node_modules` still held TypeScript 5.9.3 against a
lockfile at 7.0.2; `npm ci` reproduced both failures exactly as CI shows them.

Root causes, confirmed by reproduction:
- `tsconfig.json(5,25): error TS5108: Option 'moduleResolution=node10' has been removed.`
- `TypeError: Converting circular structure to JSON` from `@eslint/eslintrc`
  `ConfigValidator.formatErrors` while `FlatCompat.extends('next/core-web-vitals')`
  loads a legacy shareable config under ESLint 10.
- Found at the gate, behind the first: with the flat presets imported directly,
  ESLint 10 still crashes — `TypeError: Error while loading rule 'react/display-name':
  contextOrFilename.getFilename is not a function` from `eslint-plugin-react` 7.37.5
  (latest; peer `eslint ^9.7` max), which `eslint-config-next` 16.3.x depends on
  (`^7.37.0`). ESLint 10 removed `context.getFilename`. No plugin release supports
  ESLint 10, so the #99 bump cannot stand.

## Scope
- `tsconfig.json` — `module` + `moduleResolution` to `node16`
- `console/eslint.config.mjs` — import `eslint-config-next/core-web-vitals` and `eslint-config-next/typescript` flat presets directly; `FlatCompat` removed
- `console/package.json`, `console/package-lock.json` — `@eslint/eslintrc` removed (no remaining importer); `eslint` pinned back to `^9.39.5` (last major `eslint-plugin-react` supports)
- `.github/dependabot.yml` — `/console` ignores `eslint` semver-major until `eslint-plugin-react` ships ESLint 10 support
- `dist/engineos.cjs` — rebuilt; esbuild renumbered internal import bindings (`import_node_fs23` -> `24`, ...) after the resolution change, 7 lines, no behaviour change

## Notes
- `module: node16` emits CommonJS here because the root `package.json` has no `type`
  field; the `build/` output `node --test` runs is unchanged in shape.
- esbuild (`scripts/build.mjs`, `format: cjs`) did re-emit `dist/engineos.cjs` after
  the resolution change: only the numeric suffixes of its internal `import_node_*`
  bindings moved (module visit order). The CI drift guard runs `npm run build` then
  `git diff --quiet -- dist/engineos.cjs`, so the rebuilt bundle is committed.
- `next build` rewrote `console/tsconfig.json` (`jsx: react-jsx`, `.next/dev/types`
  include); reverted, out of scope. CI's console job does not diff-check it.
- The flat-config rewrite stays under ESLint 9: `eslint-config-next` 16 exports flat
  arrays, so `FlatCompat` / `@eslint/eslintrc` are dead weight either way.
- The real TypeScript 7 adoption question (tsgo, `--noEmit` speed, any semantic
  drift) is not this change; this only restores the option TS 7 removed.
